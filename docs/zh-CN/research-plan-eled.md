# EleD 研究与案例方案

## 项目定位

EleD 首先是一个软件项目。它的目标是为 RDKit 用户提供稳定的接口，在分子、
原子、键和片段层级计算、保存并复用 xTB 电子结构信息。研究案例用于证明
这些接口可以接入常见的机器学习流程；EleD 本身不变成一个新的预测模型，
也不声称重新发明量子化学布居分析。

核心问题是：

> 研究者能否从 RDKit 分子直接得到带原子/键索引的电子结构特征、质量诊断和
> 一个小型 ML/GNN 实验，而不需要自己编写 xTB 解析器，也不丢失原子和键的身份？

## EleD 核心已经提供的能力

核心包负责计算器、扩展版 `libxtb` 运行时约定、描述符提取、来源信息、缺失值
语义、构象分析和 RDKit 原生可视化。核心测试覆盖单位、守恒、不变性、
native/compiled 一致性和失败报告。模型训练和数据集相关代码放在可导入的
`eled` 包之外，也不进入核心 CI。

## 系统边界和交付物

项目分成四层，每层有独立的验收条件：

| 层级 | 仓库位置 | 产物 | 验收条件 |
| --- | --- | --- | --- |
| 描述符引擎 | `src/eled/`、`cpp/rdXTBTools/` | `XTBResult` 和带索引的描述符报告 | 单位、守恒、不变性、失败语义以及 native/compiled 一致 |
| 特征归档 | `tools/run_*_features.py`、协议 JSON | 带原子/键身份的版本化 JSON/JSONL | 协议哈希、坐标哈希、覆盖率和明确缺失原因 |
| 应用案例 | 外部研究工作区 | 可供模型消费的归档和研究报告 | 固定数据划分、未触碰的测试集和可复现指标 |
| 研究产物 | `docs/`、release 归档 | 报告、环境锁定和校验和 | 不改变核心 API 即可复现实验 |

数据流固定为：

```text
RDKit Mol + 构象
        │
        ▼
扩展版 libxtb 单点 / 可选优化
        │
        ▼
XTBResult（C、S、AO 映射、能量、电荷、来源信息）
        │
        ├── 描述符报告和 RDKit 注释
        └── 版本化特征归档 ──► 表格模型 / GNN 案例
```

这样软件贡献可以独立使用。替换数据集或模型时，描述符接口、报告 schema
和数值测试仍然保持稳定。

## 软件验证问题

案例需要回答四个实际问题：

| 问题 | 证据 |
| --- | --- |
| 用户能否从 RDKit 分子开始？ | 一次文档化的计算器调用，以及保留原子/键编号的报告 |
| 电子特征能否复用？ | 同一归档可以供表格模型和图适配器消费，不重复计算 |
| 新增信息的成本是多少？ | 按特征组报告引擎调用次数、运行时间和存储量 |
| 结果是否可检查？ | 单位、不变性检查、覆盖率、缺失原因和协议哈希 |

主要的软件易用性结果是从 `ROMol` 到模型特征的短流程。预测指标用于证明
案例流程，归档复用、来源信息和计算成本用于证明 EleD 本身。

## 研究案例

### 案例 A：分子级表格模型

选择一个小型公开分子性质数据集，并固定三维坐标或固定 SMILES 到构象的准备
规则。生成带版本的 EleD 特征表，用 ridge、随机森林或梯度提升等简单模型训练。
至少报告：

- 目标、数据源版本和许可证；
- 分子与几何 manifest；
- RDKit-only 特征和 EleD 特征组；
- 覆盖率、失败率、运行时间和特征计算成本；
- 留出集性能、不确定性和可复现实验脚本。

RDKit-only 模型只是检验特征是否有用的最小控制，不是要求 EleD 必须超过某个
GFN1 方法，也不设置 GFN1 优势作为验收条件。

### 案例 B：原子级 EAS 模型

在原子映射和许可证可以复现的前提下，使用有版本的 RegioML/RegioSQM 风格
EAS 公开导出。这个案例是应用验证，不定义 EleD API。使用 EleD 生成节点特征，
使用带 RDKit 键编号的描述符生成边特征，然后训练小型原子分类/排序模型或
message-passing GNN。需要展示同一个特征归档可以同时供表格模型和图模型使用。

主要结果是能力报告：标签覆盖率、描述符覆盖率、失败原因、运行时间、分子级
划分和留出集排序指标。结构特征模型可以作为最小控制。GFN1、已发表的
RegioSQM 特征或其他系统的比较属于可选消融，不应成为 EleD 的验收条件。

### 可选案例 C：图级迁移

在 A、B 稳定后，再使用第二个小型公开任务检验同一套 `XTBResult` 节点/边 schema
能否被图模型直接消费，而不改变描述符接口。该案例关注 schema 复用和开发者
体验，不追求 state-of-the-art。

## 固定案例协议

每个案例有独立的机器可读协议，记录数据源和版本、分子筛选、构象准备、xTB
方法和温度、特征组、划分种子、模型种子、指标和输出物。特征协议与案例协议
的哈希写入每个归档。查看结果后不得悄悄更改几何、原子编号或缺失值处理。

协议有三个检查点：

1. **计算前：** 冻结数据源身份、筛选规则、构象设置、特征组、随机种子和划分规则；
2. **特征生成后：** 在查看测试集前冻结 manifest、归档哈希、覆盖率和失败表；
3. **模型完成后：** 与归档哈希一起发布模型配置、留出集预测、不确定性和环境信息。

共同电子计算协议为：

- 只使用扩展版 `libxtb`；
- 除非案例另有说明，主几何或单点特征使用 GFN2；
- 主分析使用 300 K，1000 K 只作为电子占据敏感性诊断；
- 密度、shell、前线和 π 描述符使用 `keep_overlap=True`；
- 保留失败行和缺失原因，特征生成阶段不填零；
- 缺失值填补、标准化和特征选择只在训练集内部拟合。

## 外部模型研究边界

EleD 发布特征归档合约以及使用这些特征所需的来源信息。模型代码、超参数文件、
数据集、训练权重和统计结果放在独立的研究工作区中维护。它们不由 `eled` 导入，
不进入 EleD 测试套件，也不随 EleD 仓库发布。

外部研究必须消费冻结后的归档，保留分子身份和原子/键编号，在训练前冻结测试集，
并记录完整环境和模型配置。外部工程可以使用表格模型或 GNN，报告留出集指标、
不确定性、覆盖率和运行时间。这些结果用于证明归档可用，不改变 EleD API。

公开协议记录电子方法、几何、特征组、缺失值语义和来源字段；模型选择、超参数、
校准和统计报告由外部研究工程负责。

## 交付物

每个完成的案例至少生成：

1. 数据源和许可证记录；
2. 带原子/键编号的筛选 manifest；
3. 协议 JSON 和 SHA256；
4. 带来源和失败行的 EleD 特征归档；
5. 外部研究工程使用归档训练模型的脚本；
6. 留出集预测、指标、不确定性和覆盖率表；
7. 环境锁定文件和复现日志。

仓库只保留描述符 fixture 和特征归档合约测试。源数据、模型代码、训练模型和统计结果
放在独立研究工作区或带校验和的外部归档中。

## 里程碑

| 里程碑 | 工作内容 | 完成条件 |
| --- | --- | --- |
| M0：API 冻结 | 描述符目录、单位、结果能力和缺失原因 | 目录与核心测试通过，不依赖案例代码 |
| M1：归档冻结 | 特征导出、协议哈希、原子/键映射和失败行 | 20–50 个分子的 dry run 可复现 |
| M2：外部分子级案例 | 将冻结归档交给研究工作区 | 外部研究记录划分、模型和留出集指标 |
| M3：外部原子级案例 | 将原子标签归档交给研究工作区 | 外部研究报告覆盖率和原子级指标 |
| M4：外部图模型案例 | 消费相同的节点/边归档 | GNN 工作无需修改 EleD |
| M5：发布 | 双语案例报告、锁定文件、校验和和失败分析 | 干净环境可重现已发布产物 |

M0–M1 是软件交付物；M2–M5 是在数据源和许可证具备后独立完成的应用证明。

| 里程碑 | 状态 |

| M0：API 冻结 | 描述符目录、报告 schema 和验证套件已具备 |
| M1：归档冻结 | EAS 协议、导出器和 dry run 合约已具备，仓库没有收录公开源数据归档 |

## 执行顺序

1. 在计算特征前冻结案例协议和数据源适配器；
2. 用 20–50 个分子做 dry run，检查原子映射、覆盖率和运行时间；
3. 冻结完整 manifest 和划分，不能看完测试结果后调整筛选；
4. 先生成特征归档并完成描述符级验证；
5. 将冻结归档交给独立研究工作区进行模型训练；
6. 发布包含失败和负结果的外部案例报告，并附归档哈希和环境锁定文件。

EleD 不包含 EAS 模型适配器或训练工具。等数据、许可证和结果准备好后，
再链接到独立版本化的研究仓库。
